## 요약
뱀서라이크 생존 액션. **이동만 하면 스킬이 알아서 나가고**, 적을 잡아 젬을 모아 레벨업할 때마다 카드 셋 중 하나를 고릅니다.
라운드(8~15분)를 버티면 코인으로 상점 강화를 사고 다음 라운드로. **라운드마다 빌드는 초기화**되고 코인 · 상점 강화만 남습니다.

## 1. 개요
| 항목 | 지금 |
|---|---|
| 한 판 | 라운드의 연속(1~100). 한 라운드 = 뱀서의 한 판(8분 → 10라운드마다 +1분, 상한 15분) |
| 직업 | 6종 — 무사 · 마법사 · 궁수 + 잠금 3(광전사 5라운드 도달 · 흑마법사 한 판 진화 3 · 유랑객 누적 처치 2만) |
| 스킬 | 20종(직업마다 5 + 공용), 6레벨. 자기 직업 스킬 피해 +10%(`NvD.CLASS_BONUS`) |
| 패시브 | 5종(화약 주머니 · 속사 벨트 · 집중 렌즈 · 강철 각반 · 수호 부적), 5레벨 |
| 진화 · 유니온 | 스킬 만렙 + 짝 패시브 → 보스 상자에서 진화. 만렙 스킬 둘 → 유니온 3종(폭풍의 소용돌이 · 화산 · 화살비) |
| 리미트 브레이크 | 올릴 데가 없으면 카드가 위력 · 연사 · 범위 · 체력 · 발놀림으로 |
| 아르카나 | 판 진행 22 · 48 · 74% 에 규칙 카드 셋 중 하나(8종, 되돌릴 수 없음) |
| 적 | 5종(기본 · 질주 · 비대 · 폭탄 · 침) × 4티어(색) + 보스(변이체). 보스는 1라운드부터 최소 하나 |
| 떨어지는 것 | 젬(늘) · 동전 2% · 자석 0.3% · 구급 상자 0.5% · 보물상자(보스 100%) · 맵의 통 |
| 메타 | 코인 → 상점 9항목(방탄 조끼 · 총열 강화 · 속사 장치 · 자기장 코일 · 행운의 부적 · 저주받은 인장 · 다시 뽑기 · 건너뛰기 · 지우기) |
| 난이도 | 5단계(산책 ~ 지옥) — 적 체력 · 적 피해 · 코인 세 곱하기만 |
| 맵 | 3개(폐허 도심 · 붉은 사막 · 얼어붙은 연구소), 라운드마다 돌아감 |

## 2. 플레이어 경험 (원본 README 에서)
- 조작은 이동 하나, 고민은 "어디로 피할까 · 무엇을 고를까".
- **보스를 잡을 이유** — 진화는 보스 상자에서만(피해 다니면 진화가 없다).
- **화면만 보고 단단함을 안다** — 같은 라운드 안에서도 적의 색(티어)이 곧 체력.

## 3. 핵심 규칙 — 밸런스는 한 줄의 식
- **라운드 n 은 모든 상점 강화를 `req_lv(n)` 단계까지 올린 화력이면 클리어된다**(`NvD.req_lv` — 1라운드 0강, 100라운드 99강, `REQ_POW` 1.6 제곱).
- 라운드가 바꾸는 것은 **나오는 적의 티어 섞임 하나뿐**(`NvD.tier_mix`) — 체력 배율 · 스폰 간격 · 수는 라운드를 안 봄. 그래서 검산이 한 줄.
- 판 안 진행은 초가 아니라 **진행도**로 — 웨이브 줄은 진행도의 1.15제곱, 판 안 체력 배율(`hp_scale`)은 1.75제곱.
- 난이도는 곱하기 셋(적 체력 · 적 피해 · 코인). **경험치는 난이도를 안 탐**(어려운 쪽이 빌드가 빨라져 쉬워지는 것을 막음).
- 화면에 담기는 월드(`ZOOM`) · 스폰 거리(`SPAWN_MIN` 1020) · 맵 크기는 한 덩어리.
- 한 마리는 아이템 하나만, 아이템은 자석에 안 끌려옴(가서 줍는 대가), 실루엣이 전부 다름.

## 4. 화면 흐름 (지금)
TITLE(원본 제목) → CHARSEL(직업 · 난이도 · 시작 라운드) → PLAY → LEVELUP / ARCANA / CHEST(멈춤) → SWEEP(젬 회수) → CLEAR(상점) → PLAY … / OVER.

## 5. 조절값
`NvD` — `REQ_POW` · `HP_RAMP` · `TIER_MUL` · `DIFFICULTY` · `WEAPON` · `PASSIVE` · `UNION` · `CHAR` · `SHOP` · `ARCANA` · `WAVE` · `ENEMY_CAP`(600) · `SPAWN_MIN/MAX` · 드롭 확률.

## 6. 의존 · 미니게임 모음으로 옮기며 바꾼 것 (11-09)
- 클래스 접두어 `Nv`(젤리팝 `Art` · `D` · `G2` · `P` · `Sv` 와 겹쳐서), 저장 `user://neon.cfg` · `neon_test.cfg`, 확인용 실행은 저장 안 함.
- 소리 오토로드 → `NvSnd.s()` 한 개(허브에 붙임, 창 없는 검산에서는 트리 밖 인스턴스).
- 발광은 원본 `main.tscn` 의 환경을 코드로(스카이와 같은 방식). 나가기는 `Hub.leave`.
- 확인용: `--neon-auto`(봇이 1라운드, 10배속) · `--shot`.
- 원본 그림 PNG(부위별 몸통 · 팔다리, 약 3MB)는 **가져오지 않음** — 원본의 벡터 대체 모습으로 돈다.

## 7. 합격 기준 (지금)
- `run.bat -- --game=neon --neon-auto` 이 한 판을 끝까지(11-09: 1라운드 272초에 쓰러짐 · 레벨 29 · 처치 947).
- 허브 검사(`--hub-test`)에 여섯째 게임으로 들어 있음.
- **헤드리스 검산이 없음** — 원본은 "라운드 n 실측 오차 0.000%" 를 손으로 쟀다(README). → 8-3.

## 8. 재정비 계획 (이 문서를 기준으로 고칠 것)

### 8-1. 처음 화면을 다섯 게임과 같은 틀로 (ADR-0008)
- 왼쪽: `UiKit.title("네온 서바이버")` · 소개 · 기체 셋이 도는 그림. 단추: 왼쪽 위 게임 선택 · 오른쪽 위 음량 · 오른쪽 아래 **출격**.
- 오른쪽 메뉴: **출격 준비**(지금 CHARSEL 화면 — 기체 · 난이도 · 시작 라운드) · **무기 도감**(스킬 20 · 진화 · 유니온, `UiBook` 격자) ·
  **적 도감**(5종 × 4티어 + 보스) · **순위**(최고 라운드 · 누적 처치 · 진화 기록, `UiBook` 목록). 기록 한 줄: "최고 라운드 n · 보유 코인 n".
- 출격 = 마지막으로 고른 기체 · 난이도 · 라운드로 바로 시작(`NvSv` 에 저장).

### 8-2. 네온 화풍 — 그림 · 이펙트 (ADR-0005 조합: 코드 뼈대 + pixelfx + Cloudflare/sprite-gen)
| 부분 | 방법 |
|---|---|
| 적 5종 × 4티어 | **코드 네온 도형** — 기본 = 원 · 질주 = 삼각 · 비대 = 육각 · 폭탄 = 맥동하는 마름모 · 침 = 별. 티어 = 색(청록 → 노랑 → 주황 → 자홍) + 겹테. 수백 마리라 도형 한 번 그리기 |
| 플레이어 기체 · 보스 | 1차: 코드 네온 실루엣(무사 = 칼날형 · 마법사 = 원형 코어 · 궁수 = 화살형). **2차: Cloudflare 로 한 장 → sprite-gen `cutout`(배경) · `breathe`(숨쉬기 루프)**, 없으면 코드 |
| 스킬 이펙트 · 피격 · 폭발 · 젬 | **pixelfx** 이펙트를 스프라이트 시트로 내보내 `art/neon/fx_*.png`(작은 시트, ADR-0011 예산 안) — 없으면 지금의 코드 이펙트 |
| 바닥 | 맵 셋을 네온 격자 셋(색 · 무늬만 다름)으로, 코드 |
| 이름 | 세계관을 "격자를 갉아먹는 **글리치**를 쓸어내는 기체" 로 — 좀비 → 글리치, 직업 → 기체(이름만, 규칙은 그대로) |

### 8-3. 검산 도구 `tools/neon_check.gd` (ADR-0004)
- 그리기 없이 `NvGame` · `NvWorld` 만, 고정 dt 로 봇(피하기 + 젬 줍기 · 카드 무작위)을 돌린다.
- 볼 것: 라운드 n 에 "상점 `req_lv(n)` 강" 을 준 봇의 생존 시간 분포가 라운드끼리 비슷한가(식이 살아 있나) · 직업별 생존율 · 진화 · 유니온 발생 수 ·
  적 수가 `ENEMY_CAP` 을 넘지 않음 · NaN 없음.
- 실패(종료 코드 1): 판이 안 끝남 · 숫자 깨짐 · 적 상한 초과.

### 8-4. 소리 — 미리 굽기 (ADR-0006)
- 지금 `NvSnd` 는 `AudioStreamGenerator` 에 매 프레임 채움 → 웹(스레드 없음)에서 끊길 수 있음.
- 효과음은 켤 때 한 번 합성해 `AudioStreamWAV` 로 굳히고(젤리팝 `Snd` 와 같은 방식), 음 높이는 `pitch_scale`. 배경 음악은 허브 `Bgm` 에 "neon" 곡으로.

### 8-5. 순서
8-1 처음 화면 → 8-3 검산(재정비 전후 수치 비교용으로 먼저) → 8-2 네온 화풍 → 8-4 소리 → 2차: Cloudflare + sprite-gen 기체 · 보스 그림.

## 12. 리깅 기획 — 새 부위 그림 + 실감 나는 동작 (사용자 결정: 부위 그림은 새로, Cloudflare → sprite-gen)

### 12-1. 부위 그림 (원본 art/README 규칙 그대로)
- 종마다 6조각: `<이름>_torso` · `_head` · `_arm_b` · `_arm_f` · `_leg_b` · `_leg_f`. 이름: hero(직업 셋은 hero_warrior · hero_mage · hero_archer) ·
  zombie · runner · fat · bomber · spitter · boss — **9벌 × 6 = 54장**.
- 몸통 · 머리: 오른쪽을 보게, 가운데, 팔다리 없이. 팔 · 다리: **세로로 긴 그림, 위쪽 끝 = 관절, 곧게 뻗은 중립 자세**.
- 만드는 길(화풍을 맞추려고 부위를 따로 뽑지 않는다):
  1. Cloudflare 로 **종마다 전신 한 장**(옆모습, 팔 내리고 다리 편 자세, 마젠타 바탕) 후보 3~4장.
  2. 고른 한 장을 sprite-gen `cutout` 으로 배경을 지운다.
  3. 부위 나누기 도구(`tools/rig_split.gd`, 새로) — 종마다 적어 둔 사각형 · 다각형으로 머리 · 몸통 · 팔 · 다리를 잘라 내고,
     몸통에서 팔 자리를 지운다(원본의 DeArm 과 같은 일). 관절 자리는 표(`NvD.RIG`)에 적는다.
  4. 정지 그림에는 sprite-gen `breathe` 를 쓰지 않는다 — 숨쉬기 · 걸음은 리깅 코드가 맡는다(두 번 움직이면 떤다).
- 그림이 없으면 원본 부위(지금) → 그것도 없으면 벡터 몸(ADR-0005).

### 12-2. 동작 (코드 — `NvArt._cutout_body` 를 넓힌다)
| 동작 | 내용 |
|---|---|
| 걸음 | 디딜 때 몸이 내려앉고 차고 오를 때 올라옴(걸음 주기 두 번), 좌우 기우뚱, 머리는 몸보다 늦게 따라옴(2차 움직임) |
| 종별 걸음새 | 기본 = 질질 끌기(한 다리 늦게) · 질주 = 앞으로 기울어 달리기(보폭 큼) · 비대 = 뒤뚱(좌우 큰 흔들림) · 폭탄 = 몸이 부풀었다 줄었다 · 침 = 고개를 젖혔다 뱉기 · 보스 = 무거운 쿵(디딜 때 화면 흔들림 약하게) |
| 공격 예비 | 주인공과 가까우면 팔을 치켜들었다 내려치기(접촉 피해 순간과 맞춤) |
| 맞음 | 맞은 쪽 반대로 몸이 젖혀졌다 돌아옴(넉백 방향) |
| 쓰러짐 | 죽을 때 뒤로 넘어가며 흐려짐(0.4초, 적 배열이 아니라 효과 배열 — 수백 마리라 가볍게) |
| 주인공 | 스킬이 나갈 때 몸 동작 — 회전 참격 = 몸통 회전 · 화염구 = 지팡이 앞으로 · 화살 = 활 당겼다 놓기 |

### 12-3. 확인
- 캡처: 종마다 걷는 칸 8장을 한 장에 늘어놓는 도구(`--neon-rig-sheet`)로 걸음 · 공격 · 맞음 · 쓰러짐을 눈으로.
- 성능: 화면 안 적 300마리에서 프레임(원본 `_pick_tier` 의 단계 내리기는 유지).
- 검산(`neon_check`)은 그리기와 무관 — 수치가 그대로인지만.

### 12-4. 순서
① 동작 코드(지금 부위 그림으로 먼저 — 그림을 바꿔도 동작은 그대로 쓴다) → ② 전신 프롬프트 9종 · 후보 뽑기(Cloudflare 한도) →
③ 고르기 → cutout → 부위 나누기 → 관절 표 → ④ 캡처 확인.
