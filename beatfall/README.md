# 비트폴 (Beatfall)

Godot 4 / GDScript. 세로 낙하형 4·6키 리듬게임입니다. 위에서 내려오는 노트를
판정선에 맞춰 치고, 정확도와 콤보로 점수를 냅니다.

**노트를 치면 그 자리의 음이 납니다.** 곡을 노트 시각으로 잘라 조각을 만들고
각 조각을 그 노트에 붙였습니다(비트매니아·BMS 의 키음 구조). 그래서 —

- 다 맞히면 **원곡 그대로** 나옵니다
- 밀려서 치면 그 음도 밀려 나와 **박자가 흐트러져 들립니다**
- 놓치면 그 음이 **아예 안 납니다**

타격음은 없습니다. 원곡 위에 없는 소리를 얹으면 곡을 방해하고, 무엇보다
음악 자체가 이미 피드백이기 때문입니다. 자세한 건 아래
[키음](#키음)과 [음이탈](#음이탈)을 보세요.

**mp4 를 넣으면 오디오를 뽑아 채보를 자동으로 만듭니다.** 곡은 exe 옆
`songs/` 폴더에서 실행 중에 읽으므로, 곡을 더 넣는다고 다시 빌드할 필요가 없습니다.

## 조작

| | |
|---|---|
| 4키 | `D` `F` `J` `K` |
| 6키 | `S` `D` `F` `J` `K` `L` |
| 배속 | `[` `]` (판 도중에도 됩니다) |
| 판정 보정 | 곡 선택 화면에서 `C` |
| 타격음 켜기/끄기 | 곡 선택 화면에서 `H` (기본 끔) |
| 키음 켜기/끄기 | 곡 선택 화면에서 `K` (기본 켬) |
| 자동 연주 | 곡 선택 화면에서 `F2` (기록은 안 남습니다) |
| 나가기 | `Esc` |

곡 선택은 `↑` `↓` 곡 · `←` `→` 난이도 · `Enter` 시작이고, 마우스 클릭도 됩니다.
화면 아래 토글 넷(`C` `K` `H` `F2`)도 눌러서 바꿀 수 있습니다.

## 실행과 빌드

```
cd beatfall
run.bat            소스에서 바로 실행
build.bat          내보내기 (dist\beatfall.exe + dist\songs\)
check.bat          자체 검사 — 수치를 만졌으면 여기부터
check.bat sweep    온셋 문턱 격자 탐색
import.bat <파일>  mp4/mp3/wav 에서 곡 하나 만들기
```

엔진은 `C:\tools\godot\Godot_v4.7.1-stable_win64_console.exe` 를 기본으로 찾고
`GODOT_BIN` 환경 변수로 바꿀 수 있습니다.

## 곡 넣기

```
import.bat "C:\어딘가\노래.mp4"
import.bat "C:\어딘가\노래.mp4" 내가붙인이름
```

[ffmpeg](https://ffmpeg.org/download.html) 이 PATH 에 있어야 합니다
(`winget install Gyan.FFmpeg`). 하는 일은 넷입니다.

1. `ffmpeg` 로 재생용 `audio.ogg` 를 뽑습니다.
2. `ffmpeg` 로 **두 층**(`bed.ogg` · `keys.ogg`)으로 나눕니다 — [키음](#키음) 참고.
3. `ffmpeg` 로 분석용 22050Hz 모노 16bit wav 를 뽑습니다.
4. 헤드리스 Godot 이 그 wav 를 분석해 `chart.json` 을 만들고,
   **두 층의 합이 원곡인지 잔차를 재서 찍습니다.**

결과는 `songs/<이름>/` 에 `audio.ogg` · `bed.ogg` · `keys.ogg` · `chart.json`
네 파일로 남고, 게임을 켜면 목록에 바로 나옵니다. 난이도는 EASY · NORMAL ·
HARD(4키) · MANIAC(6키) 넷이 한 번에 만들어집니다.
4분짜리 곡에 30초 안팎 걸립니다(대부분 ffmpeg 인코딩 시간입니다).

**영상은 버립니다.** Godot 은 Ogg Theora 만 재생할 수 있어서 뮤직비디오를 쓰려면
통째로 다시 인코딩해야 하는데, 리듬게임에서 배경 영상이 주는 값어치보다 비쌉니다.

곡 폴더는 그냥 폴더라 손으로 옮기거나 지워도 되고, `chart.json` 을 편집기로 열어
제목·노트를 직접 고쳐도 됩니다.

## 키음

[src/keys.gd](src/keys.gd). **노트를 친 그 순간에 그 자리의 음이 납니다.**

곡을 노트 시각으로 잘라 조각을 만들고 각 조각을 그 노트에 붙입니다.
조각은 이어 붙이면 원곡이 그대로 나오도록 **빈틈없이** 곡을 덮습니다.

| 판정 | 들리는 것 |
|---|---|
| PERFECT | 조각이 제자리에서 나온다 → 원곡 그대로 |
| GOOD (±120ms) | 조각이 120ms 밀려 나온다 → 박자가 흐트러져 들린다 |
| MISS | 조각이 안 난다 → 음이 빈다 |

### 두 층

진짜 BMS 는 작곡가가 악기별 트랙을 따로 만들어 둬서 **한 악기만** 빠집니다.
**믹스를 자르면 그 구간의 모든 악기가 같이 빠집니다** — 이미 섞인 소리를 다시
나눌 수는 없기 때문입니다. 그래서 두 층으로 나눕니다.

| 층 | 내용 | 언제 나는가 |
|---|---|---|
| **바닥층** `bed.ogg` | 180Hz 아래 (베이스·킥) | 계속 흐른다 |
| **키음층** `keys.ogg` | 나머지 전부 | 조각으로 잘려 노트에 붙는다 |

한 번 틀려도 리듬이 완전히 끊기지 않고, 무엇보다 **바닥층이 오디오 시계
역할을 합니다.** 곡 전체를 노트에 매달면 음이 빌 때 [Conductor](src/conductor.gd)
가 볼 시계가 같이 사라집니다 — 판정의 기준이 없어지는 것이라 게임이 안 됩니다.

**나눌 때 1차(6dB/oct) 필터를 씁니다.** 기울기가 완만해서 층끼리 조금 새지만,
1차 저역과 1차 고역은 **더하면 정확히 원신호로 돌아옵니다.** 더 가파른 필터는
덜 새는 대신 합이 원곡이 아니게 되고, 그러면 "다 맞히면 원곡 그대로"가
거짓말이 됩니다. `import.bat` 이 매번 잔차를 재서 찍습니다.

| | |
|---|---|
| 데모 곡 (진짜 스템 분리) | 최대 오차 1 / 32000 |
| level5 (주파수로 나눔) | 잔차 −39.4 dB |

데모 곡은 이벤트 표에서 나오므로 악기를 골라 렌더할 수 있습니다 — **진짜 스템
분리**라, 키음 구조를 시험하기에 제일 좋은 곡입니다.

### 끄기

곡 선택 화면에서 `K`. 예전처럼 곡 전체를 통으로 재생합니다.
`bed.ogg`·`keys.ogg` 가 없는 옛 곡 폴더도 자동으로 이 모드로 돌아갑니다.

## 음이탈

[src/warp.gd](src/warp.gd). **틀리면 음악 자체가 무너집니다.**

MISS 나 BAD 가 뜰 때마다 `warp` 값이 오르고(`D.WARP_MISS` · `D.WARP_BAD`)
시간이 지나면 내려갑니다(한 번 놓치면 0.75초, 완전히 무너지면 2.5초).
그 값이 음악 버스에 세 가지로 걸립니다.

| | 중립 (다 맞힐 때) | 최대 (완전히 무너졌을 때) |
|---|---|---|
| 로우패스 | 20000 Hz | 520 Hz — 먹먹해집니다 |
| 코러스 흔들림 | wet 0 (안 섞임) | wet 0.85, 깊이 22ms — 음정이 출렁입니다 |
| 볼륨 | 0 dB | −7 dB |

키음이 켜져 있으면 음이탈은 `D.WARP_WITH_KEYS`(0.45)만큼 **약하게** 걸립니다.
**둘 다 세게 걸면 서로 잡아먹습니다** — 키음이 켜지면 틀린 자리에서 소리가 아예
비므로 그것만으로 충분히 읽히고, 음이탈은 거들기만 하면 됩니다.

### 왜 음정 이동을 안 쓰는가

"음이탈" 이라면 `AudioEffectPitchShift` 로 음정을 내리는 게 제일 곧이곧대로지만
두 가지가 걸립니다.

1. FFT 기반이라 **버스에 얹는 것만으로 항상 지연이 생깁니다.** 그 지연은
   `AudioServer.get_output_latency()` 에 안 잡혀서 [Conductor](src/conductor.gd) 가
   모릅니다. 상수라 캘리브레이션으로 흡수되긴 하지만, 판정의 기준선을 흔드는 값을
   효과 하나 때문에 들여올 이유가 없습니다.
2. `pitch_scale = 1.0` 이어도 그래뉼러 처리가 원음을 미세하게 상하게 합니다.
   **"다 맞히면 원곡 그대로"가 이 기능의 전제**인데 그게 깨집니다.

지금 쓰는 셋은 중립값에서 **수학적으로 통과**입니다 — 로우패스는 차단 주파수가
가청 대역 밖, 코러스는 `wet = 0`(마른 소리만), 볼륨은 0dB. `check.bat` 이
이걸 매번 확인합니다. **로우패스 기본값이 2000Hz 라 특히 위험합니다** —
얹기만 하고 안 올려 두면 멀쩡한 곡이 처음부터 먹먹하게 들리는데, 귀로는
"원래 이런 곡인가" 싶어서 눈치채기 어렵습니다.

### 들어 보기

```
run.bat -- --autoplay --song=0 --diff=2 --miss=8
```

자동 연주가 8노트마다 하나씩 **일부러 놓칩니다.** 사람이 일부러 틀려 가며 듣는
것보다 고르게 들려서 세기를 맞출 때 편합니다.

> `--miss` 를 켜면 자동 연주에 GREAT 이 조금 섞이는데 **싱크 문제가 아닙니다.**
> 건너뛴 노트가 판정창을 다 지날 때까지 그 레인의 커서에 남아 있어서, 바로 뒤
> 노트가 늦게 눌립니다. 사람이 칠 때는 안 생깁니다. 성능을 의심하기 전에
> `--miss` 없이 한 번 돌려 보세요 — 그때는 키음을 켜든 끄든 전부 PERFECT 입니다
> (level5 HARD 1310노트 기준 실측).

## 자동 채보가 하는 일

[src/analyze.gd](src/analyze.gd). 순서는 이렇습니다.

1. **대역별 스펙트럼 플럭스** — 1024 샘플 창으로 FFT 를 걸어 6개 주파수 대역의
   에너지를 구하고, 프레임 사이에 **늘어난 몫**만 남깁니다. 소리가 커지는 순간이
   곧 사람이 박으로 듣는 지점입니다.
2. **지역 적응 문턱으로 봉우리 따기** — 고정 문턱을 쓰면 조용한 구간에서 아무것도
   안 잡히고 시끄러운 구간에서 전부 잡힙니다.
3. **BPM 과 첫 박 추정** — 온셋 포락선의 자기상관.
4. **격자에 붙이고, 세기 순으로 잘라 난이도별 밀도를 맞추고, 대역으로 레인 배정.**
   낮은 소리는 왼쪽, 높은 소리는 오른쪽에 둡니다.

### 지금 성능 (데모 곡 기준, `check.bat`)

| | |
|---|---|
| 재현율 (실제 소리를 놓치지 않는가) | 91.6% |
| 정밀도 (없는 걸 만들지 않는가) | 93.6% |
| 시각 편차 중앙값 | +0.2 ms |
| BPM 추정 | 129.2 (실제 128) |
| 롱노트 비율 | 6 ~ 11% |

## 지켜야 할 제약

### 오디오 시계가 전부입니다

[src/conductor.gd](src/conductor.gd) 가 이 게임에서 제일 중요한 파일입니다.

- **`_process` 의 delta 를 더해서 곡 위치를 세지 마세요.** 프레임이 한 번 튀면
  그 오차가 영구히 남고, 3분짜리 곡이면 끝에서 100ms 넘게 밀립니다. 그 상태에서는
  판정창을 아무리 다듬어도 곡 후반이 통째로 안 맞습니다.
- 진짜 시계는 `AudioStreamPlayer.get_playback_position()` 이고, 여기에
  `AudioServer.get_time_since_last_mix()` 를 **더하고**
  `AudioServer.get_output_latency()` 를 **뺍니다.**
- **판정용(`pos`)과 그리기용(`smooth`) 시계를 나눠 두었습니다.** 원값은 믹스 블록
  단위라 계단처럼 움직여서 그대로 그리면 노트가 떨리고, 다듬은 값으로 판정하면
  정확도를 잃습니다.
- **캘리브레이션(`C`)은 장식이 아닙니다.** 블루투스 이어폰은 100ms 넘게 밀립니다.
  중앙값을 쓰세요 — 평균은 실수로 크게 어긋난 입력 하나에 통째로 끌려갑니다.

### 판정과 채보

- **판정창(`D.WINDOW`)은 사람 손의 한계가 아니라 화면과 소리의 지연을 감안한
  값입니다.** 60Hz 화면은 프레임 하나가 16.7ms 이고 오디오 출력 지연이 보통
  15~30ms 입니다. PERFECT 를 20ms 로 조이면 아무리 잘 쳐도 안 뜨는 기기가 생깁니다.
- **노트 시각은 박이 아니라 초입니다.** 박으로 두면 BPM 이 흔들리는 실제 녹음에서
  곡 후반이 통째로 밀립니다 — mp4 에서 뽑은 곡은 클릭 트랙에 맞춰 연주한 것이
  아니므로 대부분 흔들립니다. BPM 은 격자 표시와 채보 생성기가 참고할 뿐입니다.
- **한 손으로 못 치는 배치를 만들지 마세요.** 같은 레인에 `D.AN_SAME_LANE_GAP`
  (85ms) 안에 두 번 오면 안 됩니다. `check.bat` 이 "겹침" 으로 셉니다.
- **롱노트는 누르고 있는 동안 그 레인을 통째로 차지합니다.** 자리 배정에서 끝나는
  시각을 넣어 둬야 그 위에 다른 노트가 얹히지 않습니다.
- **체감 난이도는 노트 밀도가 아니라 `D.SCROLL_SEC` 가 정합니다.** 값이 크면
  촘촘한 구간이 뭉쳐 보이고, 작으면 노트가 갑자기 튀어나옵니다.

### 자동 채보를 만질 때

- **`D.AN_THRESH_SD` 를 올리지 마세요.** "근처에 큰 소리가 있으면 문턱이 같이
  올라간다"는 뜻이라, 스네어 옆의 하이햇처럼 **조용하지만 박을 이루는 소리가
  통째로 사라집니다.** 1.10 이던 시절 재현율이 67% 였고, 놓친 것이 정확히
  엇박이었습니다 — 채보에 4분음표만 남아 밋밋해집니다.
- **온셋 시각은 FFT 창의 시작이 아니라 가운데입니다.** 시작으로 잡으면 채보가
  곡보다 평균 20ms 빨라지고, PERFECT 창이 ±42ms 이므로 정확히 친 사람이
  GREAT 를 받습니다.
- **소리가 언제 끝나는지는 밀집된 편곡에서 정확히 잴 수 없습니다.**
  `An._sustain` 은 그래서 보수적입니다 — 끝나는 것을 실제로 못 봤으면 롱노트로
  만들지 않습니다. 없는 롱노트는 손가락을 붙잡아 그 뒤 노트까지 놓치게 해서,
  없는 일반 노트보다 훨씬 나쁩니다. 이 판단을 완화했다가 채보의 60~90%가
  롱노트가 된 적이 있습니다.
- **문턱을 감으로 정하지 마세요.** `check.bat sweep` 이 격자를 훑어 재현율과
  정밀도를 같이 보여 줍니다. 하나를 올리면 다른 하나가 내려가는 맞바꿈이라
  한쪽만 보고 고치면 반대쪽이 조용히 나빠집니다.

### 그리기와 성능

- **노드를 만들지 마세요.** 노트는 `Dictionary` 배열이고 `_draw()` 한 곳에서
  그립니다. 3분 채보는 노트가 2천 개입니다.
- **노트 한 장은 그리기 호출 두 번**(몸통 + 윗면)입니다. 빠른 구간에는 화면에
  60~80장이 동시에 깔리므로 한 겹만 늘어도 비용이 그만큼 곱해집니다.
- **판정은 레인마다 따로 커서를 밉니다.** 한 배열을 앞에서부터 훑으면 레인 0 의
  노트를 기다리는 동안 레인 3 의 노트가 커서에 막힙니다.
- **효과음은 켤 때 한 번 렌더해 굳혀 둡니다**([src/snd.gd](src/snd.gd)).
  좀비디펜스처럼 매 프레임 샘플 단위로 합성하면, 초당 10번 넘게 나는 타격음이
  그대로 프레임을 먹습니다 — 그러면 노트가 떨려서 못 칩니다.
- **`_draw()` 에는 클리핑이 없습니다.** 노트는 `clip_contents` 를 켠 `Control`
  자식 안에서 그립니다. HUD 는 그 다음에 추가한 레이어에 그려야 가려지지 않습니다.
- **화면 가운데 위아래는 비워 둡니다.** 노트가 거기서 내려오고 거기서 판정됩니다.
  점수·체력은 전부 필드 양옆입니다. 콤보만 판정선 위에 둡니다 —
  시선이 이미 거기 고정돼 있어서, 옆으로 빼면 콤보가 끊긴 걸 눈치채지 못합니다.

### 색

- **레인 색과 판정 색이 겹치면 안 됩니다.** 노트는 청록·보라, 판정은 금·초록·
  주황·적입니다. 겹치면 화면이 빨라졌을 때 잘 치고 있는 건지 노트가 쌓인 건지
  순간적으로 구분이 안 됩니다.
- **레인마다 다른 색을 주지 마세요.** 바깥(양 끝)과 안쪽 두 가지뿐입니다.
  예뻐 보이지만 빠른 구간에서 색이 정보가 아니라 소음이 됩니다.

## 테스트

`check.bat` 이 네 가지를 봅니다.

. **키음 조각표가 곡을 빈틈없이 덮는가** — 틈이 있으면 다 맞혀도 그 자리가 비고,
   겹치면 같은 소리가 두 번 나서 울립니다. 두 층의 합이 원곡인지도 같이 잽니다.
3. **데모 채보가 사람이 칠 수 있는 모양인가** — 시각 순서, 한 손 겹침, 롱노트 비율.
4. **자동 채보가 실제 소리를 찾아내는가** — 내장 데모 곡은 **소리와 채보가 같은
   표에서 나오므로 정답을 압니다.** 그 곡을 분석기에 넣고 재현율·정밀도·시각 편차를
   잽니다. 실제 mp4 로는 이 검산이 불가능합니다.

게임 쪽은 자동 연주로 확인합니다. **전부 PERFECT 가 나와야 합니다** — 치는 쪽도
판정하는 쪽도 같은 시계를 보기 때문입니다. GREAT 이하가 섞이면 시계가 두 갈래로
흐르고 있다는 뜻입니다.

```
run.bat -- --autoplay --song=0 --diff=2
run.bat -- --autoplay --song=0 --diff=2 --miss=8    일부러 8노트마다 하나씩 놓친다
run.bat -- --shot=out.png --shot-at=60              화면 캡처 (자리 배치 확인용)
check.bat demo-song      데모 곡을 wav 로 굳혀 자동 채보까지 태운다 (ffmpeg 불필요)
```

자동 연주는 게임 안에서도 `F2` 로 켤 수 있습니다. `--autoplay` 는 곡 선택을
건너뛰고 바로 시작할 뿐입니다.

> **캡처는 실제보다 훨씬 어둡게 나옵니다** — `hdr_2d` 라 선형 공간으로 저장됩니다.
> 밝기로 판단하지 말고 자리만 보세요.

수치를 만졌으면 위를 돌린 뒤 **직접 2~3분 쳐 보세요.** 배속과 판정 보정은
사람이 쳐 봐야만 알 수 있습니다.
