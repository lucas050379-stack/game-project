# 랜덤 디펜스 (Random Defense)

워크래프트3 유즈맵 **ORDR(원피스 랜덤 디펜스)** 의 규칙을 옮긴 디펜스입니다.
Godot 4 / GDScript, 로우폴리 3D.

유닛은 고를 수 없습니다. **위습**으로 무작위 유닛을 뽑고, 정해진 **조합법**에 맞춰
서로 다른 유닛을 모아 상위 등급을 만듭니다. 유닛은 타워가 아니라 **움직이는 유닛**이라
워크래프트처럼 드래그로 여러 기를 골라 옮깁니다.

```
위습 → 무작위 유닛 → 조합법대로 모아 상위 등급 → 다시 재료로
```

## 실행

```
cd random-defense
build.bat        내보내기 (dist\random-defense.exe 한 파일)
sim.bat          헤드리스 난이도 검산
test.bat         조합 판정 검사 (쉬움/보통 각각)
```

엔진은 `C:\tools\godot\Godot_v4.7.1-stable_win64_console.exe` 를 기본으로 찾고,
`GODOT_BIN` 환경 변수로 바꿀 수 있습니다. 내보내기 템플릿 4.7.1 이 필요합니다.

## 조작

| 입력 | 하는 일 |
|---|---|
| 왼쪽 드래그 | 상자 안의 유닛을 모두 고릅니다 (`Shift` 로 추가) |
| 왼쪽 클릭 | 유닛 하나 고르기 |
| 오른쪽 클릭 | 고른 유닛들을 그 자리로 보냅니다 (격자로 펴서 섭니다) |
| `A` | 전체 선택 |
| `V` | 유닛 머리 위 초상 끄기 / 켜기 |
| `Q` | 위습으로 유닛 뽑기 |
| `W` | 위습으로 나무 도박 (목재 0~3, 꽝 있음) |
| `E` | 목재 3으로 랜덤 도박 (50%, 실패하면 행운의 토큰) |
| `F` | 목재 1로 **압살롬 도박** (33%) |
| `G` | 골드 400으로 위습 사기 |
| `R` | 스토리 보상 위습 쓰기 (받은 순서대로 그 등급에서 뽑습니다) |
| `T` | 흔함 선택 위습 쓰기 (아홉 종 중에서 직접 고릅니다) |
| `Tab` | **전체 조합표** 열기 / 닫기 (`←``→` 등급, `↑``↓` 줄, `PgUp``PgDn` 쪽) |
| `Enter` | 조합표에서 커서가 놓인 조합 만들기 |
| `1`~`6` | **고른 유닛의 진화 목록**에서 골라 조합 |
| `F5` | 게임이 끝난 뒤 다시 시작 |
| `Esc` | 종료 |

## 난이도 — 시작할 때 고릅니다

**적의 세기는 둘이 완전히 같습니다.** 라운드도 보상도 그대로고, 다른 것은 **조합의
번거로움** 하나뿐입니다. 이 게임에서 실제로 어려운 것은 전투가 아니라 247개짜리 조합
트리를 머리에 담는 일인데, 그걸 난이도로 삼을 이유가 없기 때문입니다.

| | 쉬움 `1` | 보통 `2` |
|---|---|---|
| 조합 | **모자란 재료를 만들어서라도 이어 붙입니다** | 조합법에 적힌 재료를 그대로 갖춰야 |
| 전체 조합표 | 줄마다 **최하위 유닛이 종류별로 몇 개 드는지** 한 줄 더 | 바로 위 재료만 |

쉬움은 "최하위 재료로도 된다"가 아니라 **"중간에 무엇이 있든 이어 붙는다"** 입니다.
조로와 칼병은 있는데 하찌만 없고 하찌의 재료는 있다면, 하찌를 먼저 만들어서라도 잇습니다.
그렇게 몇 단계든 내려가므로 최하위 재료만 있는 경우도 자연히 포함됩니다.

```
쉬움 · 전체 조합표
🖼 캡틴크로       조로 0/1 · 칼병 0/1 · 하찌 0/1                최하위 4
   최하위        조로 0/1 · 나미 0/1 · 칼병 0/1 · 총병 2/1
```

진화 목록에서는 그렇게 이어 붙일 때 `자동` 표시가 붙고, 만들어서 채울 재료는 **금색**
(갖춘 것은 옥색, 아예 없는 것은 붉은색)으로 나옵니다.

**쉬움에서도 조합법 쪽을 먼저 봅니다.** 중간 유닛을 이미 만들어 뒀다면 그걸 쓰는 것이
맞고, 재료를 다시 요구하면 이미 합쳐 버린 것을 또 모으라는 말이 됩니다.

> **이 판정은 두 번 잘못 만들었습니다.** ① 조합법 그대로만 봤더니 최하위 재료를 들고도
> 안 됐고, ② 조합법 **또는** 끝까지 펼친 재료 두 가지만 봤더니 **절반쯤 합쳐 둔 판**이
> 오히려 막혔습니다. 지금은 재귀로 내려가며 이어 붙입니다(`Game._spend`).
> 화면에서는 "왜 조합이 안 되지"로만 보여서 원인이 안 드러나므로, `test.bat` 으로 검사합니다.

## 규칙

### 지는 조건

맵에는 **처음도 끝도 없습니다.** 몬스터는 고리 모양 트랙을 끝없이 돌고, 안 죽으면 계속 쌓입니다.
**살아 있는 몬스터가 100마리가 되면 집니다.** 코어도 목숨도 없고, 화면에 깔린 몬스터 수가
그대로 남은 여유입니다.

라운드는 30초마다 넘어가고 그때마다 한 무리가 더 풀립니다. 보스는 **10라운드마다 딱 한 마리**입니다.

### 위습 · 목재 · 골드

| 자원 | 어디서 | 무엇에 |
|---|---|---|
| **위습** | 시작 10개 + 라운드마다 4개 | 유닛 뽑기 / 나무 도박 (하나에 하나) |
| **목재** | 나무 도박 | 랜덤 도박 · 압살롬 도박 · **조합 재료** |
| **골드** | **몬스터를 잡으면** (마리당 12, 보스 240) | 위습 사기 (400골드) |

- 나무 도박은 목재 0~3개 (기대값 약 1.08). **꽝이 28%** 라서 도박입니다
- 목재 3개로 **랜덤 도박** — **50%** 로 랜덤전용·특수함 유닛, 실패하면 **행운의 토큰**이
  남습니다(그것도 조합 재료입니다)
- 목재 1개로 **압살롬 도박** — 33%. **꽝이어도 목재는 사라집니다**
  (안 그러면 도박이 아니라 그냥 기다리면 되는 일이 됩니다)

**골드를 라운드 보상이 아니라 처치 보상으로 둔 이유**는, 밀리고 있을 때는 골드도 안 들어오기
때문입니다. 격차가 벌어지는 판에서 보상까지 얹어 주면 되돌릴 수 없는 상태가 오래 이어집니다.

> **압살롬은 다른 길이 없어서 따로 뒀습니다.** 조합법이 `나미 ×1 + 좀비 ×3` 인데 좀비가
> 안흔함이라 스토리 보상(1·2·4단계)으로만 나오고, 그 좁은 뽑기에서 같은 유닛을 셋이나
> 모으는 것은 사실상 불가능합니다.

### 얻을 길이 없던 재료들

ORDR 에서는 연구소 건설·기록지침 해금·특성 포인트 같은 **게임 밖 진행**으로 풀리는 것들이
있는데, 이 게임에는 그 통로가 없습니다. 그대로 두면 그 위 조합법이 통째로 막힙니다.

| 무엇 | 어떻게 |
|---|---|
| `목재` | **자원으로 잇습니다.** 조합법의 목재는 보유 목재에서 나갑니다 — 이것 하나가 조합법 **95개**를 막고 있었습니다 |
| `랜덤전용유닛 1기` | **랜덤전용 등급 아무거나 하나**로 채워집니다(나루토 선인모드·메구밍 등). 특정 유닛이 아니라 표식입니다 |
| `초월쿠마` | 스토리 10단계 선택 보상에 넣었습니다 |
| `행운의 토큰` | 랜덤 도박 실패 보상 |
| 기록지침 · 연구소 · 아이템 전부, 그리고 기타의 `태양신의 흔적` `우타의 헤드셋` `불사조의 깃털` `슈스이` `그린블러드` `금 5,000/10,000/30,000` `특성포인트 x 4` | **조합법에서 뺐습니다**(25종, 조합법 32개가 고쳐짐). 유닛 자체는 표에 남습니다 |

그 결과 **조합법 247개를 전부 만들 수 있습니다**(고치기 전에는 145개).

> **재고에서 재료를 빼는 곳은 `Game._take_one` 하나뿐입니다.** 특수한 재료가 둘 —
> 목재는 유닛이 아니라 자원이고, `랜덤전용유닛 1기` 는 등급 하나를 통째로 가리킵니다.
> 판정마다 따로 처리하면 어디 하나는 반드시 빠뜨립니다.
>
> 실제로 `_take` 가 **목재를 자원에서 먼저 빼는** 바람에, 판에 목재 유닛이 서 있으면
> 그 유닛이 안 사라진 채 조합이 끝나는 버그가 있었습니다(검사가 재료 12기 중 7기가
> 그대로 남은 것을 잡았습니다). 지금은 유닛부터 없애고 **모자란 만큼만** 자원에서 뺍니다.

재료를 빼는 목록은 [tools/gen_units.ps1](tools/gen_units.ps1) 의 `$stripGrades` · `$stripNames`
에 있습니다. **`src/units.gd` 를 손으로 고치지 말고 생성기를 고친 뒤 다시 돌리세요.**

### 조합

3중첩이 아니라 **지정 조합법**입니다. 서로 다른 유닛 2~4종을 정해진 대로 모아야 합니다.

```
핸콕 (희귀함) = 나미x3 + 로빈 + 브룩 + 핸콕(특별함)
```

**조합은 유닛을 딱 한 기 골랐을 때만 합니다.** 고르면 그 유닛으로 갈 수 있는 진화 목록이
뜨고, 숫자키로 바로 만듭니다. 만들어진 유닛은 곧바로 고른 상태가 되어 그다음 진화가 이어집니다.

```
조로  흔함                                             1기 선택
역할 물뎀    초당 18    사거리 7.0
──────────────────────────────────────────────────────────────
진화 가능 7 — 숫자키로 조합                                …외 1
[1] 캡틴크로       특별함    조로 1/1 · 칼병 1/1 · 하찌 0/1
[2] 파이러츠도킹5  특별함    조로 1/1 · 프랑키 1/2
[3] 쿠마           특별함    조로 1/1 · 프랑키 1/1 · 베포 0/1
[4] 브룩           안흔함    조로 1/1 · 쵸파 0/1
```

- 재료마다 `가진 수 / 필요 수` 를 붙이고, 채운 것은 옥색 · 모자란 것은 붉은색입니다
- **부족한 재료가 적은 것부터** 줄 세웁니다 — 등급 순으로 놓으면 손도 못 대는 최상위가
  맨 위에 오고, 정작 하나만 더 모으면 되는 것이 아래로 밀립니다
- 재료가 모자란 줄도 **번호를 그대로 둡니다.** 목록에서 빼면 번호가 계속 바뀌어
  "3번을 눌렀는데 다른 게 나왔다"가 됩니다

> 예전에는 판 전체의 조합 가능 목록을 따로 띄웠는데, 줄이 수십 개가 되면서 정작
> 지금 고른 유닛으로 무엇을 할 수 있는지가 묻혔습니다. 그래서 걷어냈습니다.

### 전체 조합표 (`Tab`)

247개 조합법을 **등급으로 갈라 쪽 단위로** 봅니다. 재료마다 지금 가진 수가 같이 붙어 있어,
표를 넘기다가 "이건 하나만 더 모으면 되네"가 바로 읽힙니다. **표에서 바로 조합할 수도
있습니다**(`Enter`) — 고른 유닛을 거치지 않으므로 넘겨 보다 발견한 조합을 그 자리에서
시도할 수 있습니다.

```
전체 조합표  특별함 33종     [←][→] 등급  [↑][↓] 줄  쪽 1/3  [Enter] 조합  [Tab] 닫기
▁▁▁ ███ ▁▁▁ ▁▁▁ ▁▁▁ ▁▁▁ ▁▁▁ …
🖼 압살롬          나미 0/1 · 좀비 0/3                        최하위 4
🖼 캡틴크로        조로 0/1 · 칼병 0/1 · 하찌 0/1              최하위 4
▌🖼 징베          버기 1/1 · 에이스 0/1 · 후쿠로 2/1          최하위 5   ← 왼쪽 금색 띠 = 지금 만들 수 있음
```

줄 커서는 배경으로, "지금 만들 수 있음"은 **왼쪽 금색 띠**로 알립니다. 둘 다 배경색이면
커서가 어디 있는지 안 보입니다.

### 캐릭터 그림

**판 위의 유닛은 머리 위에 초상이 뜹니다**(`V` 로 끄고 켭니다). 3D 도안은 역할 3종뿐이고
등급은 색과 크기로만 내므로, 초상이 없으면 같은 등급 유닛이 판에서 전부 똑같이 생겨
특정 캐릭터를 눈으로 찾을 수가 없습니다. 고른 유닛은 테두리가 굵어지고 이름이 함께 뜹니다.

3D 쪽에 `Sprite3D` 를 유닛마다 붙이는 대신 **HUD 에서 화면 좌표로 찍습니다.** 노드를
안 만들어도 되고, 멀든 가깝든 초상 크기가 일정해서 오히려 읽기 쉽습니다.

유닛 목록·조합표·선택창에도 같은 아이콘이 붙습니다.

```
powershell -ExecutionPolicy Bypass -File tools\fetch_icons.ps1
```

ORDR 조합 도우미가 쓰는 아이콘(52×39)을 유닛 id 별로 받아 `art/icons/<id>.png` 에 둡니다.
이미 받은 것은 건너뛰므로 여러 번 돌려도 됩니다.

- **그림이 하나도 없어도 게임은 돌아갑니다.** `Ico.tex()` 가 없으면 `null` 을 돌려주고
  등급 색 네모를 대신 그립니다 — 자리를 비우면 그림 없는 유닛만 줄이 밀려 목록이 들쭉날쭉해집니다.
- 그림은 **HUD 에서만** 씁니다. 3D 쪽 유닛은 로우폴리 도안 그대로입니다.
- PNG 는 빌드 때 PCK 로 묶이므로 **배포 파일은 여전히 exe 하나**입니다(310장에 exe가 104.5 → 108.0MB).

유닛은 **310종 / 20등급**입니다.

| 등급 | 종수 | 평균 재료 | | 등급 | 종수 | 평균 재료 |
|---|---|---|---|---|---|---|
| 흔함 | 9 | — | | 초월함 | 36 | 92.6 |
| 안흔함 | 14 | 1.9 | | 불멸의 | 12 | 138.5 |
| 특별함 | 33 | 4.5 | | 영원한 | 12 | 128.5 |
| 희귀함 | 44 | 12.7 | | 신비함 | 13 | 95.8 |
| 전설적인 | 40 | 42.3 | | 기타·특수함·랜덤전용 등 | 49 | 조합 불가 |
| 히든조합·왜곡됨·변화된·제한됨 | 44 | 26.8~89.4 | | | | |

"평균 재료"는 **끝까지 펼쳤을 때 흔함 유닛 몇 개가 드는가**입니다. 가장 비싼
`니카(뱀초)` 는 172개, 깊이 7단계입니다.

### 역할

유닛마다 **물뎀 · 마뎀 · 스토리** 역할이 있습니다. 몬스터는 종마다 물리·마법 저항이 달라서
같은 세기라도 상대에 따라 덜 들어갑니다. `방무` 태그를 가진 유닛은 이걸 통째로 무시합니다.

전투에 쓰이는 태그는 `범위 · 둔화 · 스턴 · 방무 · 끝딜 · 보스` 여섯입니다.

### 스토리 진행맵

오른쪽에 붙은 별도의 판입니다. **유닛을 직접 그쪽으로 옮겨야** 싸움이 시작되고,
그만큼 본진 방어가 얇아집니다 — "언제 보낼지"가 이 게임의 두 번째 결정입니다.

1~14단계이고, 한 단계를 깰 때마다 **보상 위습 하나 + 흔함 선택 위습 하나**를 줍니다.

| 단계 | 보상 위습 |
|---|---|
| 1 · 2 · 4 | 안흔함 |
| 3 · 5 · 6 · 7 · 11 · 12 · 13 · 14 | 특별함 |
| **8 · 9** | **희귀함** |
| **10** | `희귀함 레일리 / 해적선 / 초월쿠마 / 목재 5` 중 선택 |

**초월쿠마는 조합으로도 뽑기로도 안 나오므로 10단계가 유일한 통로입니다.**

**희귀함은 8·9단계와 10단계 선택 보상뿐입니다.** 자주 주면 스토리 한 번으로 본진 화력이
해결돼 라운드를 버티는 의미가 사라집니다.

**흔함 선택 위습**(`T`)은 아홉 종 중에서 직접 고릅니다. 무작위 뽑기로만 흔함을 모으면
마지막 한 종이 끝내 안 나와서 트리가 통째로 막히는데, 고를 수 있는 흔함이 조금씩
들어와야 "이 조합법을 노린다"가 계획이 됩니다.

> **스토리가 상위 등급의 실질적인 관문입니다.** 검산해 보면 스토리 없이 100라운드를 돌려도
> 최고 등급이 희귀함에서 멈춥니다 — 전설 이상의 조합법이 `레일리(히든)` · `해적선` ·
> `초월쿠마` 같은 **기타 등급**을 재료로 요구하는데, 이건 위습으로는 안 나오기 때문입니다.

## 데이터는 어디서 왔나

유닛 명단과 조합법은 ORDR 조합 도우미 페이지(`docs/onerand.txt`)에서 그대로 옮겼습니다.

- `tools/gen_units.ps1` 이 그 HTML 을 읽어 `src/units.gd` 를 만듭니다. **`src/units.gd` 는
  손으로 고치지 마세요** — 다시 돌리면 덮어씁니다.
- 조합 트리는 사이트가 계산해 둔 "끝까지 펼친 재료 수"와 대조해 **247종 전부 일치**하는
  것을 확인했습니다.
- 역할(물뎀·마뎀·스토리)은 원본에 필드가 없어서 툴팁의 `~로 좋아요 N` **투표 수 중 최대**로 정했습니다.
- **원본에 없어서 우리가 만든 것은 전투 수치뿐입니다.** ORDR 페이지에는 공격력·사거리가
  없으므로, 유닛의 세기는 `c`(최하위 재료 몇 개로 만들어지는가)로 잡습니다.

## 난이도

```
몬스터 한 마리의 체력 = power(n) × ROUND_TIME × HP_RAMP / 마리 수
```

`power(n)` 은 라운드 n 까지 받은 위습(`10 + 4n`)을 다 쓰고 잘 조합했을 때의 기대 초당 피해입니다.
지수를 1보다 크게 둔 것(`DPS_POW = 1.06`)이 **조합의 이득**입니다 — 재료 넷을 그대로 두는
것보다 합쳐서 하나로 만드는 쪽이 셉니다. 1.0 으로 내리면 조합할 이유가 사라집니다.

**판 전체를 조이거나 푸는 손잡이는 `D.HP_RAMP` 하나입니다.** 만졌으면 `sim.bat` 을 도세요.

현재 값은 **1.05** 이고, 잘 두는 사람 기준 3판에서 40라운드를 모두 완주하며
중반에 21~30마리, 마지막에 17~32마리가 남습니다.

> **여유 구간이 좁습니다.** 쌓이는 방식의 패배 조건이라 화력이 스폰을 못 따라잡는 순간
> 눈덩이처럼 불어납니다. 실제로 `HP_RAMP` 0.80 은 거의 안 쌓이고(1~13마리),
> 1.15 는 **17라운드에서 무너집니다.** 0.05 단위로 움직이세요.

## 만들 때 지킨 것

- **리소스 0개.** 그림 파일도 음원도 없습니다. 단일 exe 는 `export_presets.cfg` 의
  `binary_format/embed_pck=true` 로 유지됩니다.
- **유닛이 310종이지만 도안은 역할 3종뿐입니다.** 등급은 크기와 색으로만 냅니다 —
  310개를 그릴 수는 없고, 그렸다 해도 화면에서 구분되지 않습니다.
- **정점 색은 색이 아니라 명암입니다.** 회색조로만 넣고 실제 색은 `MultiMesh` 인스턴스
  색이 냅니다. 바닥만 예외입니다(인스턴스 색이 없는 통짜 메시라서).
- **면의 정점은 바깥에서 봤을 때 반시계 방향으로** 넣습니다. 순서를 섞으면 그 면만
  조명이 뒤집혀 까맣게 나오는데 원인이 눈에 안 띕니다.
- **노드를 만들지 않습니다.** 몬스터도 탄도 `Dictionary` 배열이고 종류마다 `MultiMesh` 하나입니다.
- **죽은 것을 그 자리에서 배열에서 빼지 않습니다.** 탄이 표적을 참조로 들고 있어서
  도중에 줄이면 판정이 엉킵니다. `dead` 표시만 남기고 프레임 끝에 정리합니다.
- **`draw_string` 은 `width` 를 안 주면 정렬을 무시합니다.** 가운데·오른쪽으로 맞춘 줄
  알았던 글자가 왼쪽부터 그려져 화면 밖으로 흘러나갑니다(실제로 그랬습니다).
  `Hud._txt` 가 폭을 직접 재서 시작점을 옮깁니다.
- **반대로 `width` 를 주면 줄을 바꾸는 게 아니라 잘라 버립니다.** 설명문에 썼더니 뒷부분이
  소리 없이 사라졌습니다(난이도 설명이 실제로 잘렸습니다). 여러 줄로 흘려야 하는 글은
  `Hud._wrap`(= `draw_multiline_string`)을 씁니다.
- **카메라는 삼각함수로 한 번에 구하지 않습니다.** 판의 모서리를 실제로 투영해 보고
  넘치는 만큼 물러나기를 되풀이합니다.
- **판을 넓게 잡지 마세요.** 카메라가 고정이라 판 전체가 늘 화면에 들어와야 하는데,
  넓힌 만큼 유닛과 몬스터가 작아집니다. 44×30 이었을 때 몬스터가 10픽셀짜리 점이었습니다.
- **PowerShell 변수는 대소문자를 구분하지 않습니다.** `gen_units.ps1` 에서 유닛 맵 `$U` 와
  반복 변수 `$u` 가 같은 변수라 맵이 통째로 덮인 적이 있습니다.
