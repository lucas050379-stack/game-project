# 드래곤 대시 (DRAGON DASH)

**세로 스크롤 무한 러너.** 화면을 끌어서 좌우로만 움직이고, 브레스는 자동으로 나갑니다.
부딪히면 그 자리에서 끝입니다. 달린 거리(m)가 점수이고, 금화로 산 강화는 죽어도 남습니다.

안드로이드 APK 가 본체입니다. Godot 4 (GDScript) · **외부 리소스 0개** —
드래곤 · 적 · 바위 · 금화 · 하늘까지 전부 코드로 그립니다.

```
build.bat         APK + Windows exe 전부
build.bat apk     APK 만
build.bat win     Windows 만
run.bat           소스에서 바로 실행 (항상 테스트 빌드)
soak.bat          헤드리스 무인 주행 — 수치를 만졌으면 여기부터
```

| 파일 | 용도 |
|---|---|
| `dist\dragon-dash.apk` | **안드로이드.** 디버그 서명. 폰에 그대로 설치됩니다. |
| `dist\dragon-dash.exe` | Windows. 손보면서 확인할 때 씁니다(마우스 드래그 = 터치). |
| `dist\dragon-dash-test.exe` | Windows 테스트 빌드. `J` 로 1000m 건너뛰기, `K` 로 저장 지우기. |

세 개가 **같은 소스**에서 나옵니다. 테스트 기능은 `D.test_build()` 하나로 가릅니다
(`testmode` 기능 태그 또는 디버그 빌드). **배포 APK 에는 그 분기가 아예 안 걸립니다** —
조건문을 여기저기 흩뿌리지 말고 이 함수 하나만 보세요.

## 조작

**화면 아무 데나 잡고 끌면 끈 만큼 드래곤이 움직입니다**(상대 드래그).
손가락 위치로 절대 이동시키면 드래곤이 손가락 밑에 깔려 안 보입니다.

| 입력 | 동작 |
|---|---|
| 드래그 (터치 · 마우스) | 좌우 이동 |
| ← → · A D | 좌우 이동 (PC) |
| 탭 | 메뉴 · 결과 화면의 버튼 |
| Enter · Z | 시작 / 결정 (PC) |
| R | 죽은 뒤 바로 다시 (PC) |
| Tab | 상점 열기/닫기 (PC) |
| `J` `K` | **테스트 빌드 전용** — 1000m 건너뛰기 / 저장 지우기 |

## 드래곤 셋

**세기는 셋이 같습니다**(`D.POWER_DPS`). 다른 것은 **브레스가 자라는 방향**입니다 —
같은 화력을 굵게 뭉치느냐, 넓게 펴느냐, 앞을 뚫느냐. 한 마리만 세면 고를 이유가 사라집니다.

| | 축 | 기본 | 파워업이 자라는 방향 |
|---|---|---|---|
| **화룡** | 집중 | 굵은 불줄기 하나 | 줄기가 계속 두꺼워집니다. 골렘과 관문에 강합니다. |
| **뇌룡** | 확산 | 갈라지는 번개 2줄기 | 부채처럼 벌어지고, 만렙은 폭을 둔 채 촘촘해집니다. 제일 빠릅니다. |
| **빙룡** | 관통 | 적을 뚫는 얼음창 | 창이 길고 굵어집니다. 세로로 줄지어 오는 무리를 꿰뚫습니다. |

파워업 `P` 는 **난수가 아니라 거리마다 하나씩** 나옵니다(120m, 이후 260m 마다).
확률로 두면 운 좋은 판은 앞에서 만렙이 되고 운 나쁜 판은 끝까지 맨몸이라,
같은 거리가 판마다 다른 게임이 됩니다.

## 적

**특수 행동은 종류 번호가 아니라 `art` 로 가릅니다.** 번호로 비교하면 종류를 늘릴 때
반드시 한 군데를 빠뜨립니다.

| | 체력 | 성격 |
|---|---|---|
| 임프 | 12 | 좌우로 흔들며 내려옵니다. 물량 담당. |
| 도깨비불 | 8 | 제일 빠릅니다. 위에서 곧장 떨어집니다. |
| 골렘 | 64 | 느리고 단단합니다. **앞을 막는 벽**이라 녹여야 길이 열립니다. |
| 와이번 | 26 | 크게 휘며 침을 뱉습니다. |
| 마법구 | 34 | 자리를 잡고 탄을 뿌립니다. |
| **바위** | — | **부술 수 없습니다.** 벽으로 나와 통로 한 칸만 남깁니다. |

- **적이 쏜 것은 분홍 하나로 통일**했습니다. 브레스(드래곤 색)에도 금화(금색)에도 안 쓰는
  색이라야 "분홍은 피한다"가 굳습니다. 색만으로는 부족해서 검은 테두리 + 맥동 고리로
  형태까지 다르게 했습니다 — 협곡처럼 배경이 밝으면 색만으로는 안 읽힙니다.
- **예비 동작(`World.CAST`) 없이 나가는 탄은 만들지 마세요.** 즉발이면 피할 방법이 없어서
  난이도가 아니라 불합리가 됩니다. 그리고 **방향은 예비 동작이 시작될 때 박아 두고 그
  뒤로 안 고칩니다** — 계속 겨냥을 고쳐 잡으면 경고를 보고 피한 사람이 그대로 맞습니다.
- **바위만 발광이 없습니다.** 화면에서 빛나는 것은 전부 "때릴 수 있는 것" 아니면
  "주울 것"이고, 바위만 빛이 없어서 눈에 바로 갈립니다.

## 구간

`ZONE_M`(1000m) 마다 배경과 웨이브 표가 바뀌고, 셋이 **계속 돌아갑니다.**

| | 성격 |
|---|---|
| 1 · 초원 | 기본형. 잡졸과 금화가 많고 바위가 가끔. |
| 2 · 협곡 | **바위가 주인공.** 절정에서 벽과 골렘이 겹쳐 골렘을 녹여야 통로가 열립니다. |
| 3 · 밤하늘 | **빠른 것과 쏘는 것.** 바위는 없습니다 — 하늘이라 그럴 자리가 없습니다. |

## 난이도는 한 줄의 식입니다 — 여기를 건드리기 전에 반드시 읽으세요

> **거리 m 는, 모든 강화를 `lv` 단계까지 올린 화력이면 도달한다**

- **`D.hp_at(m)` 이 난이도의 전부입니다.** 적 체력에만 걸리고(2000m 마다 2배),
  스폰 표 · 스크롤 속도 · 탄 수는 **거리를 보지 않습니다.**
- **스크롤 속도는 고정입니다. 거리는 곧 시간입니다.** 뒤로 갈수록 빠르게 하고 싶어지지만,
  그러면 같은 표가 거리에 따라 다른 밀도가 되어 **통로가 둘이 됩니다.**
  빨라지는 느낌은 배경 잔무늬 층에서만 냅니다.
- **밀도는 구간 안에서만 달아오릅니다.** 표의 `at` 은 구간 진행도라 거리를 안 봅니다 —
  1구간의 절정과 30구간의 절정은 **물량이 똑같고**, 다른 것은 체력뿐입니다.
  이게 "통로 하나"를 지키면서 밀도를 쓰는 방법입니다.
- **앞을 헐겁게 둔 채 뒤를 안 채우면 아무것도 안 쏘고 피하기만 해도 뚫립니다.**
  실제로 그랬습니다 — 첫 표로 무인 주행을 6분 돌렸더니 **처치 3마리로 5470m** 를 갔습니다.
  화력이 진행을 막으려면 구간 끝이 "길을 뚫지 않으면 못 지나가는" 밀도여야 합니다.

### 검산

```
soak.bat                 약 6분치 무인 주행
soak.bat 36000           프레임 수 (60 = 1초)
soak.bat 21600 3000      매 판을 3000m 에서 시작
```

한 판이 끝날 때마다 한 줄이 찍힙니다:

```
[soak]   919m  kill= 30/ 72  clear=35.4%  dps= 19.5  power=3  gold=114
```

**`clear`(뿌린 체력 대비 실제로 넣은 피해)가 핵심 지표입니다.** 낮으면 화력이 모자란 게
아니라 **브레스가 안 맞는 것**이고, 그때 `BASE_DMG` 를 올리면 엉뚱한 데를 만지는 셈입니다.
실제로 처음 clear 가 10~20% 였는데 원인은 피해량이 아니라 **브레스가 덮는 폭**이었고,
탄 폭을 2~3배로 늘려서 25~40% 로 올렸습니다.

> **봇은 사람보다 훨씬 못 칩니다(clear 25% 안팎).** 사람은 드래그로 편대를 훑고 지나가고,
> 봇은 매 프레임 점수가 제일 높은 x 하나를 고를 뿐입니다. 그래서 **봇 기록은 절대
> 난이도가 아니라 회귀 확인용 기준선**입니다 — 수치를 만진 뒤 이 값이 크게 움직였는지만
> 보세요. 실제 난이도는 직접 2~3분 플레이해서 잡아야 합니다.

**현재 기준선(0강 · 화룡 · 봇):** 중앙값 약 900m, 최대 2262m, clear 25~40%.
중앙값이 첫 구간 절정(약 900m)에 몰려 있습니다.

**아직 사람 기준으로 보정되지 않았습니다.** `D.BASE_REACH`(0강으로 가는 거리) 는
2000m 로 적혀 있지만 이건 설계 목표일 뿐 실측이 아닙니다. 직접 플레이해서 실제 거리를
재고 그 값을 넣으세요 — 그래야 `D.reach(lv)` 가 의미 있는 표가 됩니다.

## 강화는 두 갈래입니다 — 섞지 마세요

- **판 안** = 파워업 `P`. 그 판에서만 세지고, 죽으면 사라집니다.
- **판 밖** = 상점(`D.SHOP`). 금화로 사고 **영원히 남습니다.**

둘을 한 곳에 두면 "이번 판에 센 것"과 "계속 세지는 것"의 구분이 사라집니다.

| 항목 | 만렙 | 레벨당 |
|---|---|---|
| 브레스 위력 | 40 | 피해 +25% |
| 브레스 연사 | 40 | 간격 −5.5% |
| 비행 속도 | 30 | +1.2% |
| 금화 흡수 | 30 | 범위 +5% |
| 금화 가치 | 30 | +4% |
| **비늘 보호막** | **3** | 시작할 때 한 겹. 부딪히면 한 겹이 깨집니다. |

- **보호막 상한이 3인 이유:** 즉사 게임에 "한 번 봐줌"은 필요하지만, 더 주면 부딪히는 것이
  실수가 아니라 자원 소모가 되어 긴장이 통째로 빠집니다.
- **상점 값을 만지면 난이도가 통째로 따라 움직입니다.** `D.DMG_PER`·`D.RATE_PER` 를
  바꿨으면 `D.power(lv)` 를 다시 구하고 `hp_at` 곡선과 맞춰 보세요.
- 상점 화면은 **알갱이가 아니라 숫자 + 막대**입니다. 만렙 40 짜리를 칸 40개로 그리면
  폰에서 그릴 수도 읽을 수도 없습니다.

## 지켜야 할 제약

- **노드를 만들지 마세요.** 적 · 탄 · 금화는 `Dictionary` 배열로 들고 `_draw()` 한 곳에서
  그립니다. 수백 개를 노드로 만들면 생성·해제 비용만으로 폰에서 프레임이 무너집니다.
- **적을 죽일 때 배열에서 바로 빼지 마세요.** `dead` 표시만 남기고 프레임 끝의
  `_sweep()` 이 정리합니다. 판정 루프 도중에 `remove_at` 하면 뒤쪽 색인이 밀려
  엉뚱한 것을 때립니다.
- **둥근 것은 반드시 `draw_circle` 로.** `G2.fill_fan` 은 호출마다 그리기 명령이 따로 생겨
  배칭이 끊깁니다. fill_fan 은 원으로 못 만드는 실루엣에만 씁니다.
- **이펙트 배열에서 `pop_front()` 를 쓰지 마세요** — 배열을 통째로 앞으로 당기는 연산입니다.
  알갱이는 `sparks` 처럼 자리를 돌려 씁니다.
- **관통 브레스에는 `D.REHIT` 간격이 필요합니다.** 없으면 겹쳐 있는 동안 매 프레임 피해가
  들어가 초당 60번이 됩니다. 관통은 "여러 마리를 뚫는 것"이지
  "한 마리를 60배로 때리는 것"이 아닙니다.
- **지형과 같이 흘러가는 것은 반드시 `D.SCROLL` 을 그대로 씁니다**(바위). 속도를 따로
  적으면 반드시 어긋나서 "바위가 배경 위를 떠다니는" 느낌이 납니다.
- **새 화면을 만들면 키 분기와 탭 분기를 둘 다 채우세요.** 키만 넣으면 PC 에서는 되기
  때문에 "폰에서 못 누른다"를 눈치채기 어렵습니다.
- **자리를 내는 함수를 하나만 두고 그리기와 탭 판정이 같이 보게 하세요**
  (`Sel.card_rect` · `Shop.row_rect` · `Hud.over_rect`). 두 곳에서 따로 계산하면
  한쪽만 고쳤을 때 조용히 어긋나고, 화면만 봐서는 원인을 알 수 없습니다.
- **화면 흔들림은 월드에만 걸고 HUD 전에 되돌리세요.** `draw_set_transform` 을 안 되돌리면
  버튼이 밀려서 그린 자리와 누른 자리가 어긋납니다.
- **`window/handheld/orientation` 은 문자열이 아니라 정수 enum 입니다**(0=가로 1=세로).
  `"portrait"` 라고 적으면 조용히 무시되고 가로로 나갑니다 — 실제로 첫 APK 가 그랬습니다.
- 저장은 `user://save.cfg` 하나(금화 · 강화 단계 · 최고 기록)입니다. **읽기/쓰기가
  실패해도 게임은 기본값으로 돌아야 합니다** — 폰에서는 실제로 실패할 수 있습니다.

## APK 를 만들려면

엔진은 `C:\tools\godot\Godot_v4.7.1-stable_win64_console.exe` 를 기본으로 찾고,
`GODOT_BIN` 환경 변수로 바꿀 수 있습니다. 안드로이드 내보내기 템플릿 4.7.1 이 필요합니다.

**Godot 은 SDK · JDK · 키스토어 경로를 환경 변수가 아니라 에디터 설정에서 읽습니다.**
`%APPDATA%\Godot\editor_settings-4.7.tres` 의 세 줄이 맞아야 합니다:

```
export/android/android_sdk_path = "C:/Android/Sdk"
export/android/java_sdk_path = "C:/Program Files/Eclipse Adoptium/jdk-17.0.20.101-hotspot"
export/android/debug_keystore = "C:/Users/<사용자>/.android/debug.keystore"
```

이 기계에는 다음이 깔려 있습니다:

| | 무엇 |
|---|---|
| JDK 17 | Eclipse Temurin (`winget install EclipseAdoptium.Temurin.17.JDK`) |
| Android SDK | `C:\Android\Sdk` — 커맨드라인 도구 + `platform-tools` + `build-tools;34.0.0` + `platforms;android-34` |
| 디버그 키스토어 | `keytool -genkeypair -alias androiddebugkey -keypass android -storepass android` |

폰에 넣기: `C:\Android\Sdk\platform-tools\adb.exe install -r dist\dragon-dash.apk`
(또는 APK 파일을 그냥 폰으로 옮겨서 실행 — "출처를 알 수 없는 앱" 허용이 필요합니다.)

자동화된 테스트가 없습니다. 확인은 **빌드 성공 + 실행 + `soak.bat`** 입니다.
수치를 건드렸다면 `soak.bat` 을 돌려 `clear` 와 거리 중앙값이 크게 움직였는지 보고,
**최소 2~3분 직접 플레이**해서 파워업 속도와 화면 밀도를 봅니다.
