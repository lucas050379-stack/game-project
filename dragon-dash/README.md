# 드래곤 대시 (DRAGON DASH)

**세로 스크롤 무한 러너.** 화면을 끌어서 좌우로만 움직이고, 브레스는 자동으로 나갑니다.
드래곤플라이트 계열입니다 — **앞을 갈아버리며 나아가는 게임**이지 틈을 찾아 빠져나가는
게임이 아닙니다. 이 구분이 이 게임의 거의 전부입니다(아래 "한 번 크게 틀렸던 것" 참고).

안드로이드 APK 가 본체입니다. Godot 4 (GDScript) · **외부 리소스 0개** —
드래곤 · 적 · 보스 · 운석 · 금화 · 지형까지 전부 코드로 그립니다.

```
build.bat         APK + Windows exe 전부
build.bat apk     APK 만
build.bat win     Windows 만
run.bat           소스에서 바로 실행 (항상 테스트 빌드)
soak.bat          헤드리스 무인 주행 — 수치를 만졌으면 여기부터
```

| 파일 | 용도 |
|---|---|
| `dist\dragon-dash.apk` | **안드로이드.** 디버그 서명. 폰에 그대로 설치됩니다. |
| `dist\dragon-dash.exe` | Windows. 손보면서 확인할 때 씁니다(마우스 드래그 = 터치). |
| `dist\dragon-dash-test.exe` | Windows 테스트 빌드. `J` 로 1000m 건너뛰기, `K` 로 저장 지우기. |

셋이 **같은 소스**에서 나옵니다. 테스트 기능은 `D.test_build()` 하나로 가릅니다
(`testmode` 기능 태그 또는 디버그 빌드). **배포 APK 에는 그 분기가 아예 안 걸립니다.**

## 조작

**화면 아무 데나 잡고 끌면 끈 만큼 드래곤이 움직입니다**(상대 드래그).
손가락 위치로 절대 이동시키면 드래곤이 손가락 밑에 깔려 안 보입니다.
**드래그는 1:1 에 가깝습니다** — 속도 상한을 낮게 두면 급하게 그은 손가락을 몸이
못 따라와서 "피하려던 순간에 안 피해지는" 게임이 됩니다.

| 입력 | 동작 |
|---|---|
| 드래그 (터치 · 마우스) | 좌우 이동 |
| ← → · A D | 좌우 이동 (PC) |
| 탭 | 메뉴 · 결과 화면의 버튼 |
| Enter · Z / R / Tab | 시작 / 다시 / 상점 (PC) |
| `J` `K` | **테스트 빌드 전용** — 1000m 건너뛰기 / 저장 지우기 |

## 점수 — 거리 + 사냥, 그리고 근접 배율

**점수 = 비행 거리 + 사냥 점수.** 거리만 세면 "안 쏘고 피하기만 하는" 것이 최적해가
됩니다 — 실제로 그렇게 만들었다가 무인 주행이 **처치 3마리로 5470m** 를 갔습니다.

**근접 처치 보너스가 이 게임의 심장입니다.** 가까이 붙어서 죽일수록 사냥 점수가
크게 오릅니다. 이게 없으면 화면 아래에 붙어 멀리서 쏘는 것이 언제나 정답이라
드래곤을 움직일 이유가 사라집니다.

- **연속 곡선이 아니라 띠(band)입니다. 반지름이 아니라 세로 거리로 나뉩니다.**
  드래곤 위로 가로선이 그어지고 칸마다 `2X · 3X · 5X · 20X` 가 적힙니다.
  배율이 **눈에 보이는 칸**이라야 "저기까지 끌어들여서 잡는다"는 판단이 생깁니다.
  부드러운 곡선이면 왜 이번엔 7배고 저번엔 12배인지 알 수가 없습니다.
- **선을 그리는 곳과 점수를 계산하는 곳이 `D.CLOSE_BAND` 하나를 같이 봅니다.**
  따로 두면 보이는 것과 들어오는 점수가 어긋나고, 그건 화면만 봐서는 못 찾습니다.

## 드래곤 셋

**세기는 셋이 같습니다**(`D.POWER_DPS`). 다른 것은 **브레스가 자라는 방향**입니다.

| | 축 | 기본 | 파워업이 자라는 방향 |
|---|---|---|---|
| **화룡** | 집중 | 굵은 불줄기 하나 | 줄기가 계속 두꺼워집니다. 보스와 운석에 강합니다. |
| **뇌룡** | 확산 | 갈라지는 번개 2줄기 | 부채처럼 벌어집니다. 제일 빠릅니다. |
| **빙룡** | 관통 | 적을 뚫는 얼음창 | 창이 길고 굵어집니다. 줄지어 오는 무리를 꿰뚫습니다. |

**브레스는 알갱이가 아니라 줄기입니다.** 화룡의 불기둥은 만렙에서 화면 폭의 1/4쯤
됩니다 — 처음엔 폭 6px 짜리 동그라미였고, 그래서 뿌린 적 체력의 20~25% 밖에 못
죽였습니다. 목표는 `soak` 의 `clear` **80% 이상**입니다.

파워업 `P` 는 **난수가 아니라 거리마다 하나씩** 나옵니다(110m, 이후 240m 마다).

## 판 안에서만 도는 아이템 넷

웨이브 표의 `item` 자리에서 하나가 무작위로 나옵니다. **넷 다 시간제입니다** —
영구히 붙는 것을 여기 두면 판 밖 강화(상점)와 구분이 사라집니다.

| | 효과 |
|---|---|
| 듀얼샷 | 브레스가 두 줄기로 나갑니다 |
| 자석 | 화면의 금화가 전부 끌려옵니다 |
| 하이퍼 플라이트 | 무적으로 돌진합니다. 스치는 적이 전부 터집니다 |
| 더블 스코어 | 점수가 두 배로 들어옵니다 |

## 적

**특수 행동은 종류 번호가 아니라 `art` 로 가릅니다.** 번호로 비교하면 종류를 늘릴 때
반드시 한 군데를 빠뜨립니다.

| | 체력 | 성격 |
|---|---|---|
| 임프 | 11 | 좌우로 흔들며 내려옵니다. 물량 담당. |
| 도깨비불 | 8 | 제일 빠릅니다. 위에서 곧장 떨어집니다. |
| 골렘 | 58 | 느리고 단단합니다. 앞을 막습니다. |
| 와이번 | 24 | 크게 휘며 침을 뱉습니다. |
| 마법구 | 32 | 자리를 잡고 탄을 뿌립니다. |
| **운석** | 92 | 제일 단단하고 빠릅니다. 시커멓게 떨어집니다. |
| **불꽃 몬스터** | 20 | **죽으면 터져서 주변 적을 같이 없앱니다.** |
| **보물 상자** | 70 | 부수면 금화가 쏟아집니다. |

- **부술 수 없는 것은 하나도 없습니다.** 한때 바위를 못 부수게 두고 통로 한 칸만
  비우는 벽으로 썼는데, 그 순간 게임이 "쏴서 길을 연다"가 아니라 "안 맞는 칸을 고른다"가
  됐습니다 — 장르가 통째로 바뀝니다. 운석은 벽이 아니라 **날아오는 것**입니다.
- **적이 쏜 것은 분홍 하나로 통일**했습니다. 브레스에도 금화에도 안 쓰는 색이라야
  "분홍은 피한다"가 굳습니다. 검은 테두리와 맥동 고리로 형태까지 다르게 했습니다.
- **운석만 발광이 없습니다.** 화면에서 빛나는 것은 대체로 "주울 것"이라, 어두운 것
  하나가 섞이면 눈에 바로 갈립니다. **불꽃 몬스터는 반대로 혼자만 이글거립니다** —
  "이걸 먼저 노린다"가 읽혀야 폭발이 수 읽기가 됩니다.
- **예비 동작(`World.CAST`) 없이 나가는 탄은 만들지 마세요.** 방향은 예비 동작이
  시작될 때 박아 두고 그 뒤로 안 고칩니다 — 계속 겨냥을 고쳐 잡으면 경고를 보고
  피한 사람이 그대로 맞습니다.

## 보스

**구간 끝(`D.BOSS_AT`)마다 나옵니다.** 러너가 끝없이 흐르기만 하면 리듬이 없습니다 —
"여기까지 왔다"를 찍어 주는 것이 보스입니다.

- **보스와 싸우는 동안 거리가 멈춥니다.** 보스에게 자기 무대를 주기 위해서입니다.
  안 멈추면 보스가 다음 구간까지 따라 들어와 웨이브 표와 겹칩니다.
- **못 잡으면 날아가 버립니다**(`BOSS_TIMEOUT` 20초). 반드시 잡아야 넘어가게 하면
  화력이 모자란 순간 그 자리에서 게임이 멈춥니다 — 러너에서는 그게 제일 나쁩니다.
  대신 **빨리 잡을수록 점수가 큽니다**(`BOSS_FAST_BONUS`).
- 절반 이하로 깎이면 2페이즈 — 발사가 빨라지고 탄이 늘어납니다.
- 패턴 셋(부채꼴 · 고리 · 세 줄기)의 **경고 모양이 서로 다릅니다.** 다 같은 붉은
  고리면 "뭔가 온다"까지만 알고 어디로 피할지를 모릅니다.

## 난이도 — 통로가 셋입니다 (일부러)

난이도를 올리는 통로가 **셋**입니다: **적 체력 · 스크롤 속도 · 구간 안의 밀도.**

이 저장소의 다른 게임(좀비디펜스 · 갈루가)은 통로를 하나로 묶어 등식으로 검산합니다.
**여기서는 일부러 그러지 않았습니다.** 러너는 여러 축이 한꺼번에 조여드는 것이 곧
재미이고, 원작 소개도 "더 멀리 갈수록 비행 속도가 빨라지고 적들이 강해진다" 한 줄입니다.
하나로 묶으면 10분을 달려도 첫 1분과 같은 게임이 됩니다.

**대신 대가를 치릅니다: 수치를 증명할 수 없습니다.** `soak.bat` 은 "크게 망가지지
않았나"만 보고, 실제 난이도는 직접 2~3분 플레이해서 잡습니다.

- 적 체력: `D.hp_at(m)` — 2600m 마다 2배
- 스크롤: `D.scroll_at(m)` — 9000m 마다 +1배, 1.9배에서 멈춤
- 밀도: 웨이브 표가 **구간 안에서** 달아오르고, 구간마다 똑같이 되풀이됨

## 한 번 크게 틀렸던 것

처음 만든 것은 **드래곤플라이트가 아니라 회피 게임**이었습니다. 원인이 셋이었고
전부 제가 만든 것이라, 같은 실수를 되풀이하지 않도록 적어 둡니다.

1. **못 부수는 바위 벽을 넣었습니다**(원작에 없음). 그 순간 "쏴서 길을 연다"가
   "안 맞는 칸을 고른다"가 되어 장르가 바뀌었습니다.
2. **화력이 너무 약했습니다.** `clear` 가 20~25% 였습니다 — 눈앞의 적 넷 중 셋이
   그냥 살아서 지나가는 게임이었습니다. 원인은 피해량이 아니라 **브레스가 덮는 폭**
   이었고, 그걸 모르고 `BASE_DMG` 만 올렸다가 아무것도 안 나아졌습니다.
3. **스크롤 속도를 고정했습니다.** "난이도 통로는 하나여야 한다"는 이 저장소의 규율을
   그대로 가져왔는데, 러너에서는 그게 장르의 핵심을 깎아먹습니다.

그리고 **근접 처치 보너스가 통째로 빠져 있었습니다.** 원작이 즉사인데도 사람들이
적에게 파고드는 이유가 그것 하나인데, 없으니 화면 아래에 붙어만 있는 게임이었습니다.

## 검산

```
soak.bat                 약 6분치 무인 주행
soak.bat 36000           프레임 수 (60 = 1초)
soak.bat 21600 3000      매 판을 3000m 에서 시작
```

한 판이 끝날 때마다 한 줄이 찍힙니다:

```
[soak]   4918m  score=  46554  kill=250/480  clear= 73.9%  dps= 154.5  x20  pw=5
```

**`clear`(뿌린 체력 대비 실제로 넣은 피해)를 먼저 보세요.** 낮으면 화력이 모자란 게
아니라 **브레스가 안 맞는 것**이고, 그때 `BASE_DMG` 를 올리면 엉뚱한 데를 만지는
셈입니다. 이걸 몰라서 한 번 헛돌았습니다.

> **봇은 사람보다 못 칩니다.** 사람은 드래그로 편대를 훑고 지나가고, 봇은 매 프레임
> 점수가 제일 높은 x 하나를 고를 뿐입니다. 특히 **봇은 근접 배율을 노리지 않습니다** —
> 사람은 점수를 위해 일부러 파고들지만 봇은 안전한 쪽만 고릅니다. 그래서
> **봇 점수는 사람 점수와 비교하면 안 됩니다.** 회귀 확인용 기준선일 뿐입니다.

**현재 기준선(0강 · 화룡 · 봇):** 거리 2769~4918m · 점수 28k~51k · `clear` 74~98% ·
처치 137~250마리. 이 값이 크게 움직였으면 무언가 망가진 것입니다.

## 강화는 두 갈래입니다 — 섞지 마세요

- **판 안** = 파워업 `P` + 시간제 아이템 4종. 죽으면 사라집니다.
- **판 밖** = 상점(`D.SHOP`). 금화로 사고 **영원히 남습니다.**

| 항목 | 만렙 | 레벨당 |
|---|---|---|
| 브레스 위력 | 40 | 피해 +25% |
| 브레스 연사 | 40 | 간격 −5.5% |
| 비행 속도 | 30 | +1.2% |
| 금화 흡수 | 30 | 범위 +5% |
| 금화 가치 | 30 | +4% |
| **하트** | **3** | 부딪혀도 한 칸만 깎입니다. 없으면 즉사. |

**하트 상한이 3인 이유:** 즉사 게임에 "한 번 봐줌"은 필요하지만, 더 주면 부딪히는 것이
실수가 아니라 자원 소모가 되어 긴장이 통째로 빠집니다.

상점 화면은 **알갱이가 아니라 숫자 + 막대**입니다. 만렙 40 짜리를 칸 40개로 그리면
폰에서 그릴 수도 읽을 수도 없습니다.

## 지켜야 할 제약

- **노드를 만들지 마세요.** 적 · 탄 · 금화는 `Dictionary` 배열로 들고 `_draw()` 한 곳에서
  그립니다. 수백 개를 노드로 만들면 생성·해제 비용만으로 폰에서 프레임이 무너집니다.
- **적을 죽일 때 배열에서 바로 빼지 마세요.** `dead` 표시만 남기고 프레임 끝의
  `_sweep()` 이 정리합니다.
- **둥근 것은 반드시 `draw_circle` 로.** `G2.fill_fan` 은 호출마다 그리기 명령이 따로
  생겨 배칭이 끊깁니다.
- **이펙트 배열에서 `pop_front()` 를 쓰지 마세요** — `sparks` 처럼 자리를 돌려 씁니다.
- **관통 브레스에는 `D.REHIT` 간격이 필요합니다.** 없으면 겹쳐 있는 동안 매 프레임
  피해가 들어가 초당 60번이 됩니다.
- **지형과 같이 흘러가는 것은 `scroll_at(m)` 배율을 같이 받습니다.** 속도를 두 군데
  적으면 반드시 어긋납니다.
- **새 화면을 만들면 키 분기와 탭 분기를 둘 다 채우세요.** 키만 넣으면 PC 에서는
  되기 때문에 "폰에서 못 누른다"를 눈치채기 어렵습니다.
- **자리를 내는 함수를 하나만 두고 그리기와 탭 판정이 같이 보게 하세요**
  (`Sel.card_rect` · `Shop.row_rect` · `Hud.over_rect`).
- **화면 흔들림은 월드에만 걸고 HUD 전에 되돌리세요.** `draw_set_transform` 을
  안 되돌리면 버튼이 밀려서 그린 자리와 누른 자리가 어긋납니다.
- **HUD 가운데 위는 비워 둡니다.** 적이 거기서 내려오므로 글자를 놓으면 서로 가립니다.
  재화는 왼쪽 위, 거리(M)는 오른쪽 위입니다.
- **`window/handheld/orientation` 은 문자열이 아니라 정수 enum 입니다**(0=가로 1=세로).
  `"portrait"` 라고 적으면 조용히 무시되고 가로로 나갑니다 — 첫 APK 가 실제로 그랬습니다.
- 저장은 `user://save.cfg` 하나입니다. **읽기/쓰기가 실패해도 게임은 기본값으로 돌아야
  합니다** — 폰에서는 실제로 실패할 수 있습니다.

## APK 를 만들려면

엔진은 `C:\tools\godot\Godot_v4.7.1-stable_win64_console.exe` 를 기본으로 찾고,
`GODOT_BIN` 환경 변수로 바꿀 수 있습니다. 안드로이드 내보내기 템플릿 4.7.1 이 필요합니다.

**Godot 은 SDK · JDK · 키스토어 경로를 환경 변수가 아니라 에디터 설정에서 읽습니다.**
`%APPDATA%\Godot\editor_settings-4.7.tres` 의 세 줄이 맞아야 합니다:

```
export/android/android_sdk_path = "C:/Android/Sdk"
export/android/java_sdk_path = "C:/Program Files/Eclipse Adoptium/jdk-17.0.20.101-hotspot"
export/android/debug_keystore = "C:/Users/<사용자>/.android/debug.keystore"
```

이 기계에는 다음이 깔려 있습니다:

| | 무엇 |
|---|---|
| JDK 17 | Eclipse Temurin (`winget install EclipseAdoptium.Temurin.17.JDK`) |
| Android SDK | `C:\Android\Sdk` — 커맨드라인 도구 + `platform-tools` + `build-tools;34.0.0` + `platforms;android-34` |
| 디버그 키스토어 | `keytool -genkeypair -alias androiddebugkey -keypass android -storepass android` |

**안드로이드 내보내기는 `import_etc2_astc` 를 요구합니다.** 그림 파일이 하나도 없어서
실제로 압축할 것이 없는데도 켜 두지 않으면 내보내기 자체가 거부됩니다.

폰에 넣기: `C:\Android\Sdk\platform-tools\adb.exe install -r dist\dragon-dash.apk`

## 아직 안 된 것

- **런처 아이콘이 Godot 기본 로봇입니다.** 게임 그림은 전부 코드로 그리지만
  런처 아이콘만은 PNG 가 있어야 합니다.
- **난이도가 사람 기준으로 보정되지 않았습니다.** 위 "검산" 항목 참고.
- 소리가 없습니다.
- 펫(새끼용) · 캐릭터 스킬 · 보석/수정 같은 별도 재화는 없습니다. 원작에는 있습니다.

## 테스트

자동화된 테스트가 없습니다. 확인은 **빌드 성공 + 실행 + `soak.bat`** 입니다.
수치를 건드렸다면 `soak.bat` 의 `clear` 와 거리·점수가 크게 움직였는지 보고,
**최소 2~3분 직접 플레이**해서 근접 배율이 실제로 노려지는지 봅니다.
