# ADR-0012: 대상은 데스크톱 웹 브라우저 — 폰은 고려하지 않는다

- **상태:** 채택 (2026-11-09 사용자 결정 — "폰은 고려하지 않고 웹만 고려하면 될 것 같아. 앞으로도 못박아 줘")
- **층:** Foundation
- **대체하는 것:** [ADR-0007](0007-screen-and-text.md) 의 폰 근거(짧은 변 720 이 폰에서 절반, 20px 기준의 이유), [기둥 1](../pillars.md) 의 "폰 브라우저가 1순위"

## 결정
- 게임은 **데스크톱(PC) 웹 브라우저에서 마우스 · 키보드로** 하는 것을 기준으로 만들고 확인합니다.
- **폰 · 태블릿(터치 · 세로 화면 · 작은 화면)은 설계 · 검사 · 조언의 기준에서 뺍니다.**
  - 터치 영역 크기(44pt · 48dp), dp 환산, 세로 배치, 두 손가락 확대 같은 폰 기준으로 판단하지 않습니다.
  - 새 화면에 세로(`wide()` 가 거짓인) 배치를 새로 짜지 않아도 됩니다. 가로 1280×720 하나로 봅니다.
- **이미 있는 터치 · 세로 코드는 지우지 않습니다**(스카이 멀티터치 · `Hub._fit_canvas` 의 세로 캔버스 · `--touch-test`). 다만 맞춰 고칠 의무는 없고,
  그 코드 때문에 데스크톱 쪽이 불편해지면 데스크톱이 이깁니다.
- exe 는 지금처럼 손으로 확인하는 용도.

## 결과
- 글자 기준은 그대로 **캔버스 20px 이상**이되, 근거는 "1280×720 캔버스를 데스크톱 브라우저 창에 맞춰 늘려 볼 때 읽히는가" 입니다.
- 단추 크기는 **마우스로 누르기 쉬운가**로 봅니다. 지금 단추들(52~95px)은 데스크톱 기준으로 충분합니다.
- 키보드 단축키 안내(러너 "Space 시작 · Tab 속도 · Esc")는 의미가 있습니다 — 지우지 말고 읽히게.
- 용량은 여전히 중요합니다(웹 첫 로딩) — [ADR-0011](0011-texture-budget.md).
- 스크린샷 확인은 1280×720 창으로 합니다.

## 근거
2026-11-09 디자인 조언 중 사용자 결정.
